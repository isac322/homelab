# Sanitize — 공개 본문 위생

`isac-github-publishing`의 GHP-08 세부 절차. 이슈·댓글·리뷰 댓글·PR 제목·본문·라벨·릴리스 노트와 커밋되는 코드·문서 등 **GitHub에 올라가는 모든 텍스트**에 적용한다(이 자동화에서는 n8n이 게시하는 모든 결과 필드: `comment`, `issue_comment`, `pr.title`/`pr.body`, `body`, `comments[].body`, `thread_replies[].body`, `questions`, `summary`, `blockers`). 대상 저장소의 공개 여부와 무관하게 적용한다(비공개 저장소도 나중에 공개되거나 외부인이 읽을 수 있다). 사용자와의 비공개 대화(채팅 보고)에는 이 절차를 적용하지 않고 실제 이름을 써도 된다.

## 금지 항목 (공개 본문에 넣지 않는다)

- 비공개 tenant·계정·조직 식별자: tenant ID, account/zone/app/tunnel ID, AUD(audience) 값
- 실제 도메인·hostname·내부 URL·IP 주소
- 시크릿: token·key·secret의 평문은 물론 그 base64 등 인코딩 형태도 금지. 그런 값이 들어 있는 원시 로그 줄도 금지
- 클러스터·환경 식별자: namespace, 노드·app 이름, kube context 이름
- 로컬 파일 경로(`/tmp` 포함), 머신 경로
- 임시 run ID·스크래치 디렉터리 이름·임시 리소스 식별자(합성 식별자로 바꾼다)
- 비공개 저장소·조직의 내부 이름, 내부 트래커·채팅 링크(Linear, Slack 등)
- 사용자와의 비공개 대화 원문 인용, 세션·transcript ID
- 내부 에이전트·서브에이전트 이름, 내부 토론·오케스트레이션 흔적(“3개 에이전트가 토론해…” 같은 내부 과정)
- 개인 계정 식별자·고객명 등 비공개 개인 정보

## 치환 규칙

- 도메인·호스트: `example.com`, `app.example.com`
- ID·식별자: `<zone-id>`, `<account-id>`, `tenant-a` 같은 placeholder
- 재현 예시(YAML·명령·코드): 합성 값으로 바꾼 뒤에도 **실제로 실행 가능한 최소 예시**를 유지한다. sanitize 때문에 재현이 깨지면 안 된다.
- 로그·출력 인용: 금지 항목이 들어간 줄은 민감 값만 placeholder로 바꾸거나 제외하고, 의미가 바뀌게 자르지 않는다(GHP-13). 제외한 내용이 있으면 생략을 명시한다 — 조용한 제외는 금지.

## 버전·근거 고정

- 주장이 의존하는 버전·배포 tag를 명시한다.
- 코드·문서 링크는 고정 commit SHA의 permalink로 쓴다(브랜치 링크는 변한다).

## 결과에 넣기 전 체크리스트

기본: 초안 작성자가 아닌 독립 publish-review 에이전트가 초안을 결과 필드에 넣기 직전에 확인한다(단독 작업이면 메인 에이전트가 확인). 게시는 n8n이 한다:

1. 위 금지 항목이 본문·제목·라벨 description·첨부·코드 블록 어디에도 없는가.
2. 치환된 예시가 그대로 복사해 실행 가능한가.
3. 인용된 명령 출력·수치·버전이 실제 실행 결과와 일치하는가(checksum·카운트 대조). file:line 인용은 명시한 버전·SHA에서 확인했는가.
4. 링크가 모두 해석되는가(비공개 링크·깨진 링크 없음).
5. 중복 검색으로 같은 대상이 이미 있는가(GHP-09).

하나라도 걸리면 결과에 넣지 않고 초안을 고친다.
