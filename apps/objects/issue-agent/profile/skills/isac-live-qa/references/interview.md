# 사전 인터뷰 체크리스트

LQA-02·LQA-03의 세부. 질문 형식(맥락 없이 이해되는 설명, 선택지별 변화, 권장안)은 `isac-decision-brief` 스킬을 따른다. 이 자동화에서는 질문을 결과 `questions`와 댓글 필드에 넣고 턴을 끝낸다(기다리지 않는다). 답은 다음 이슈 댓글로 온다.

## 진행 방법

1. 사용자 brief를 아래 항목에 먼저 매핑한다. brief가 정한 항목은 그대로 운영 규칙으로 옮기고 묻지 않는다.
2. 저장소·환경을 읽기 전용으로 조사해 알 수 있는 사실(배포된 버전, 존재하는 namespace, 이슈 대상 저장소의 공개 여부)은 묻지 않고 확인한다.
3. 남은 불확실 항목만 한 번에 묶어 결과 `questions`(최대 5개)와 댓글 필드에 넣는다. 항목마다 권장 기본값을 제시한다.
4. 답을 받으면 확정된 경계를 한 블록으로 요약해 이후 모든 조사자 brief에 그대로 넣는다.

## 확정할 항목

| # | 항목 | 확정 내용 | 기본값(답이 없을 때) |
|---|---|---|---|
| a | 대상 환경 | 환경 식별자(kube context, cluster, 계정, URL, 기기)와 production·실사용 여부 | 추정 금지. 반드시 확인 |
| b | 대상 버전 | 검증할 버전과 배포 아티팩트(digest). 배포 버전과 main 중 무엇을 기준으로 볼지 | 배포된 아티팩트 |
| c | 기존 리소스 허용 동작 | 읽기만인지, 예외가 있는지 | 읽기만(CUD 없음) |
| d | 임시 리소스 | 생성 허용 여부, 격리 단위와 위치(namespace·테스트 계정·zone 등), 이름 규칙(run prefix), 개수·수명 | 생성 안 함(해당 케이스는 BLOCKED) |
| e | 외부·벤더 API | 조회만인지, 어떤 자격증명으로, 브라우저 로그인 필요 여부 | 조회(GET)만 |
| f | 조사 범위 | 기능, 성능, UX, 로그 기반 개선점, 설치 경로, 보안 중 무엇을 포함할지 | 전부 포함(읽기 전용 범위 안에서) |
| g | 문제 기준 | 의도된 동작의 근거(spec·문서), 개선 요청을 이슈로 올릴지, 심각도 기준 | `problem-criteria.md` |
| h | 보존 대상 | 정리 때 절대 지우면 안 되는 것(세션, 기존 PR·브랜치, 공유 fixture) | 우리가 만들지 않은 것은 전부 보존 |
| i | 산출물 | 이슈 대상 저장소, 이슈에 원인·해결까지 쓸지(깊이), 최종 보고 형태, 결과 페이지 필요 여부. 이 자동화에서는 항상 초안 모드이며 이슈 초안은 결과 댓글 필드에 넣는다 | 현상+재현 필수, 원인은 추가 노력 없이 알 때만 |
| j | 복구 조작 | 자기 임시 객체의 finalizer 제거 같은 복구 조작 허용 여부 | 금지, 필요 시 보고 후 요청 |
| k | 읽기용 자격증명 발급 | 조회를 위한 토큰 발급(TokenRequest 등)도 변경으로 보고 허용 여부 확인 | 금지 |
| l | 로컬 실행 범위 | 로컬 컨테이너·일회용 클러스터 실행 허용인지, 스크립트 작성까지만인지 | 저장소 밖 scratch 실행 허용 |
| m | 가시성 | 사용자가 실행 화면을 직접 볼지, 결과 페이지를 어디에 띄울지 | 보고서만 |
| n | 병렬성과 시간 | 공유 원격 자원 때문에 직렬화가 필요한 부분과 예상 소요 | 격리 가능한 것은 병렬 |

## 묻지 않을 것

일반적인 금지 질문(이미 승인한 배치 재질문, 진행 여부, 읽기 전용 조사 허용 여부, 맥락 없는 선택지)은 `isac-decision-brief` 스킬이 소유한다. live QA에서 추가로 묻지 않는 것:

- brief가 이미 정한 경계(LQA-03). 표현이 달라도 의미가 같으면 정해진 것으로 본다.
- 읽기 전용 조사로 확인할 수 있는 사실(배포 버전·digest, 리소스 목록, namespace 충돌, 저장소 공개 여부).

## 위험 고지 블록(승인 요청 시 포함)

LQA-05의 승인 요청에는 아래를 평이한 영어로 담는다(결과 `questions`와 댓글 필드로 GitHub에 게시되므로 `isac-github-publishing`의 언어·위생 규칙을 따른다). 틀은 `safety-and-isolation.md`의 "허용 범위 제안"이며 항목명은 영어로 옮겨 쓴다.

- 무엇을 만들고, 무엇을 읽기만 하며, 무엇은 절대 건드리지 않는가.
- 격리 경계가 어디까지 유효한가(LQA-07). 공유 계정이면 남는 위험.
- 실패하면 어떻게 되돌리는가(정리 순서, 비상 정리, 보존 대상).
- 필요한 자격증명과 각 값의 용도·권한·격리(`isac-decision-brief` 형식).
