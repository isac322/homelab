# isac-issue-to-pr 케이스

실행 중에는 읽지 않는다. 시드는 스킬을 만들 때 마이닝한 사용자 지시·교정 사례다. 원문은 인용하지 않고 요지만 적는다.

### CASE-20260927-planned-change-no-reapproval
- 상태: applied
- 출처: omp session 01a0dda6 msg 84a012fa
- 상황: 패밀리 작성 후 보고에서 에이전트가 "승인된 목표 안의 결함 수정은 다시 묻지 말라"는 교정과 전역 application-code 승인 가드가 충돌한다고 보고했다. 사용자는 충돌이 없다고 했다. 코드 변경은 계획 단계에서 이미 결정했으므로 구현 때 다시 승인받을 필요가 없고, 구현 중 다른 구조 변경이 새로 필요할 때만 다시 승인받는다.
- 대상: 이슈 수정 구현 착수 / 모든 저장소 / 애플리케이션 코드 변경 승인 / 중간(불필요한 재질문은 작업을 멈추고, 누락은 승인 없는 구조 변경이 된다)
- 적용 조건: 수정 방향이나 구조 변경 방향이 계획 단계(트리아지, 구조 변경 brief, 사용자 직접 지시)에서 결정된 뒤 그 범위를 구현할 때. 결정 범위를 넘는 새 구조 변경에는 적용하지 않는다.
- 사용자 기대: 결정된 변경은 묻지 않고 구현하고, 새로 생긴 구조 변경만 다시 묻는다.
- 실제 행동: 에이전트가 계획 단계 승인을 구현 승인으로 볼 수 있는지 확신하지 못해 전역 가드와 충돌하는 것으로 보고했다.
- 원인 분류: loose / 규칙: I2P-14
- 변경: I2P-14에 계획 단계 결정이 구현 승인을 겸한다는 문장과 재승인 조건을 추가
- 일반화: global
- 재발 확인 기준: 결정된 수정 방향을 구현하는 실행에서 같은 변경에 대한 승인 질문이 없고, 결정 밖의 구조 변경이 생긴 경우에만 isac-decision-brief 질문이 있다.
