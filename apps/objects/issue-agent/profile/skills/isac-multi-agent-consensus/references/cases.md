### CASE-20260912-parallel-too-slow

- 출처: omp session 01a095f6 msg 013c8fea, 8fc3c8c3, 928496d6
- 상황: 여러 에이전트 작업이 오래 걸리자 사용자가 정말 병렬이 맞는지 물었다.

- 적용 조건: 의존성 없는 작업 항목이 여럿인 멀티 에이전트 작업. 같은 원격 상태(공유 계정 등)를 바꾸는 작업의 직렬화는 예외다.
- 사용자 기대: 의존성 없는 작업은 최대한 병렬로 돈다.
- 실제 행동: 리서치는 병렬이었지만 공유 벤더 계정을 쓰는 원격 테스트를 직렬화했고, 계획·리뷰를 과도하게 반복해 전체가 느렸다.
- 원인 분류: not-followed / 규칙: MAC-03
- 변경: MAC-03에 병렬 원칙과 "느리면 실제 병렬인지 먼저 확인" 명시. 직렬 예외와 계획·리뷰 라운드 상한은 기본값(MAC-05, defaults §5)
- 일반화: global
- 재발 확인 기준: 독립 작업이 동시에 시작되고, 계획·리뷰 라운드가 상한 안에서 끝난다.
