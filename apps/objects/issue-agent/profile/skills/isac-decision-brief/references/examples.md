# Decision Brief 템플릿과 예시

모두 바꿀 수 있는 기본값이다. 이 자동화에서 질문은 결과의 `questions`와 초안 GitHub 텍스트로 게시되므로 `isac-github-publishing`을 따라 영어로 쓴다. 아래 한국어 템플릿은 구조만 따른다.

## 1. 승인·결정 질문 (DBR-06, DBR-08)

```
**현상**: <사용자가 보는 증상 한두 문장. 언제, 어디서, 무엇이 안 되는지>
**원인**: <확인한 원인. 근거는 파일:줄이나 실행 결과 한 줄. 추론이면 추론이라고 적는다>

**선택지**
1. <사용자 효과로 쓴 이름> (권장)
   - 바뀌는 것: <사용자 가시 결과>
   - 트레이드오프: <잃는 것, 비용, 위험>
   - 영향: <파일·리소스 preview>
2. <…>
3. 중단 — 지금 상태로 두면 <남는 문제>

**권장 이유**: <한 줄>
다른 방향이 있으면 직접 적어 주세요.
```

## 2. 나쁜 질문 → 좋은 질문 (DBR-07)

나쁨:

```
어떻게 할까요?
A. A만 (21개 kind 전체)
B. A + B
```

좋음:

```
**현상**: 새 리소스를 만들면 대시보드 상태가 "알 수 없음"으로 남습니다.
**원인**: 상태 필드를 채우는 코드가 일부 리소스 종류에만 연결돼 있습니다.

1. 모든 리소스 종류에 상태를 채운다 (권장)
   - 바뀌는 것: 어떤 종류를 만들어도 상태가 보입니다.
   - 트레이드오프: 수정 범위가 넓어 리뷰가 커집니다.
2. 이번에 보고된 종류만 고친다
   - 바뀌는 것: 보고된 경우만 해결됩니다. 나머지 종류는 같은 문제가 남습니다.
```

## 3. 여러 결정 묶기 (DBR-12)

```
결정할 것이 세 가지입니다. 2번 답에 따라 3번이 필요 없어질 수 있습니다.
1. <결정 1: 현상/원인/선택지/권장>
2. <결정 2: …>
3. <결정 3: 2번에서 "유지"를 고를 때만 해당>
```

## 4. 자격증명 요청 (DBR-15, DBR-16)

값마다 한 블록씩 쓴다.

```
### <값의 역할, 예: DNS 쓰기 토큰>
- 만드는 곳: <콘솔 메뉴 경로나 CLI 명령>
- 권한: <최소 권한. 예: 테스트 영역 하나의 DNS 편집만>
- 넣으면 바뀌는 것: <에이전트가 이 값으로 하는 작업>
- 운영과의 격리: <격리 방식(전용 계정·영역 또는 기존 영역 안 prefix 격리)과 운영 리소스를 건드리지 않는 이유. 방식이 정해지지 않았으면 DBR-19대로 트레이드오프와 함께 묻는다>
- 넣는 곳: <보안 저장소 항목 이름이나 사용자가 설정할 변수 이름>. 이 코멘트나 채팅에는 붙여 넣지 마세요.
```

## 5. 자격증명 blocker 보고 (DBR-18)

```
**막힌 곳**: <작업 단계>
**시도한 것**: <자격증명 위치·이름>(범위: <읽기 전용 등>) → <결과: 403 등>
**대체 경로**: <다른 로그 백엔드, 로그인된 CLI 세션 등> → <결과>
**필요한 것**: <정확한 권한과 대상>
```

## 6. 수동 단계 인계 (DBR-14)

```
여기서부터는 직접 해 주셔야 합니다.
1. <어디서> <무엇을> 합니다.
2. 완료되면 <확인 방법, 예: 명령 출력에 X가 보임>.
이 이슈에 완료했다고 코멘트해 주시면 <다음 단계>부터 이어서 진행합니다.
```

## 7. 조건부 진행 기록 (DBR-13)

```
조건 확인: "<사용자가 준 조건>" → 참 (<근거 한 줄>). 끝까지 진행합니다.
```

```
조건 확인: "<사용자가 준 조건>" → 거짓. <조건을 깬 항목>이 있어 현재 상태에서 멈췄습니다.
<DBR-06 형식의 현상/원인/선택지/권장>
```
